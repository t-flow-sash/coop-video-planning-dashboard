# Gmail full-message semantic candidate foundation (offline / not scheduled)

`app.ingestion.gmail_semantic` supplies `FullMessageClient(GmailConfig.from_env()).fetch(message_id) -> ParsedMessage` and `decide(messages: list[ParsedMessage], *, own_address: str, existing_track: bool) -> SemanticDecision`. `fetch` reuses `GmailClient.authorize()` (OAuth refresh, tokeninfo, profile account validation), then sends only `GET /messages/{id}?format=full` to Gmail. Its default transport streams and rejects responses above 512 KiB; MIME text, nesting, parts and messages per decision are bounded. It never fetches attachments, writes Gmail, accesses the database, persists raw bodies, or advances a checkpoint. Do not log `ParsedMessage`, transport responses or exceptions' causes.

`SemanticDecision` has separate `lead`, `status`, `deadline`, `fee` `FieldDecision`s. Each is `NO_CHANGE`, `ACCEPT`, or `REVIEW`; an accepted value has `EvidenceRef(message_id, thread_id, assertion_sha256)` references. `lead=ACCEPT` means only **candidate NEW**, not an authorized CREATE. `fee=ACCEPT` yields `{fee_amount_minor, fee_currency, fee_status: AGREED}`; invoice/payment language is never promoted to PAID. Date value is ISO-8601, status value is `CONFIRMED` only for a matched two-party explicit offer/acceptance in one thread. Any contradictory terms, drafts, conditional terms or attachment-based uncertainty require review. This intentionally narrow grammar has false negatives; it is not a legal understanding model. Same value repeated in multiple offers currently requires review. All decisions are provisional and must be reviewed against the *complete correspondence*, contracts, other threads, and publication/payment evidence. Caller must ensure the message set is complete; partial fetch is a run failure, not an acceptable decision.

## Exact handoff to `app.reviewed_domain_import` (other branch)

This branch does **not** import or invoke `apply_manifest`. The integration must be implemented separately after merging both branches:

1. Determine the real stable `track_key` and `record_key` by reviewed business-track resolution (one Gmail thread is not necessarily one track). Resolve `existing_track` from an exact link, never from fuzzy subjects/brand names. No automatic CREATE for an unknown thread without reviewed identity/title/target. Resolve each `EvidenceRef.message_id` to the persisted exact `(source_id, source_record_id, revision_id)` triple. The metadata-only collector does not store full MIME, so accepted semantic decisions must have a newly authorized, immutable, non-body semantic provenance revision before a manifest is applied; a metadata revision alone cannot certify terms. The assertion hash is a privacy-safe locator, **not** a substitute for source content or legal review.
2. REVIEW fields must not enter `fields`. NO_CHANGE fields must not enter `fields`. Accepted deadline maps to `fields.deadline`; fee maps to `fields.fee_amount_minor`, `fields.fee_currency`, `fields.fee_status`; accepted status maps to `fields.status`. For an accepted new lead, obtain reviewed required `title` and stable keys first. Avoid conflicting `lead.status=NEW` and `status=CONFIRMED`; adjudicate resulting status explicitly. Include evidence triple(s) in the `Decision.evidence` list (max 100), with non-empty list even for exclusion.
3. A reviewer constructs `schema_version=1` `Manifest`, `manifest_id`, `manifest_hash`, `Decision` with `track_revision`, `decision_hash`, `adjudication=ACCEPTED|EXCLUDED`, `action=CREATE|UPDATE|EXCLUDE`, `record_key`, and `fields`. Hashes use `app.reviewed_domain_import.canonical_hash()` excluding each corresponding hash property. For first `UPDATE` adoption, include exact `expected_version` and `expected_fields` for every field. Run `parse_manifest(raw)` then `apply_manifest(session, raw)` in a caller-owned `SessionLocal.begin()` transaction, with separate authorized writer and field-level local-edit safeguards. No auto-applying this module's outputs.
4. Any failed/oversize GET, missing inline text, incomplete MIME, unknown identity, missing revision provenance, ambiguity or local conflict blocks semantic mutation and checkpoint success under the caller's policy. Never store MIME bodies in collector revision JSON or logs. Keep OAuth token and message bodies transient. No scheduler or production credentials are wired by this branch.

Scope limitation: only inline UTF-8 plain text or sanitized HTML, and explicit EUR fee/date syntax; signed PDFs, cross-thread tracks, quoted-chain nuance, novel linguistic phrasing and status transitions beyond `CONFIRMED` require human review. `CONFIRMED` is a candidate, never proof that all obligations are final. The synthetic tests exercise the offline API and negative cases, not a live Gmail account or DB transaction.

## Operational status surface (`GET /api/v1/semantic/status`)

The authenticated read-only status endpoint is the only semantic surface the dashboard consumes. It is a typed contract (`SemanticStatus` → `SemanticSourceStatus` → `SemanticCollectorRun` in `app.schemas`, published in `packages/api-client/openapi.json`) with `extra="forbid"`, so an undeclared field fails closed instead of silently exposing evidence. Per source it reports latest-revision counts (`discovered`, `processed`, `created`, `updated`, `unchanged`, `review`, `retry`, `backlog`), `oldest_backlog_at`, `latest_evidence_at`, `last_semantic_activity`, `collector_age_seconds` and the latest `last_collector_run`. `RETRY` counts as unresolved work, `collector_age_seconds` is `null` unless the newest run succeeded, and `coverage_verified` stays `false`: message revisions are not business tracks, so these counters can never certify portfolio completeness or scheduler state. No external IDs, source keys, message bodies or credentials are part of the contract; the counters describe the *evidence* plane and do not prove that any domain record was created or updated. `apps/api/tests/test_api_contract.py` and `apps/web/tests/semantic-status-contract.test.ts` keep the checked-in contract, the published schema and the workspace types in lockstep.
